## 后端工作原理

```mermaid
flowchart LR
    Client[现有页面 / API 调试] --> API[FastAPI]
    API --> Business[Pipeline / PlaygroundStorage]
    Business --> Cache[当前进程中的 Pydantic 对象]
    Cache --> Repo[src/persistence.py]
    Repo -->|变更文档 + revision 条件| DB[(MongoDB lumenxdb)]
    DB -->|启动读取| Cache
    Business --> Files[output 媒体与文档文件]
    Files --> Static[/files HTTP 媒体服务]
```

1. 启动时从 MongoDB 读取数据并校验为现有 Pydantic 模型，不再读取业务 JSON。尚未完成显式初始化时拒绝启动，避免误展示空库。
2. 业务代码继续修改现有模型，并调用保存方法。Repository 比较已读取的快照，只写实际变化的文档，不把整张集合清空重建，也不会删除其他进程新增但本进程未知的 ID。
3. 更新/删除用 `_id + revision` 条件匹配。旧版本写入会报错，不能静默覆盖新版本。新增使用唯一 `_id`。
4. MongoDB 不可用时明确失败，不自动退回 JSON；错误内容不包含连接凭证。已有 API 的部分通用异常分支仍返回 500，未被捕获的存储冲突/连接异常分别返回 409/503。

**当前仍只运行一个 API worker。**这一步替换了持久化，没有去掉业务层内存缓存。不能据此启动多个 API worker，或让未来 monitor 通过同一份全量项目快照写库；也不要同时启动本地和 231 后端共同修改生产库。同项目冲突后应重启拥有该快照的后端再操作；写失败后内存对象也可能已变化，应重启确认数据库实际状态。

跨文档保存不是事务：前几个文档可能成功、后续文档失败，不能宣称项目与系列一次原子提交。单文档仍受 MongoDB 16 MiB 限制。下一步需要为独立任务层实现按需读取、字段级条件更新、原子领取和任务事件存储，之后才能实现你要求的 API / monitor 分离。

## 迁移、备份与回滚

脚本：

- `scripts/migrate_json_to_mongodb.py`：默认只读预检；`--apply` 先备份所有现存源 JSON，再导入并全量比对。校验全部源模型及 ID；拒绝不同内容/已更新/额外记录的目标库。相同源文件可恢复未完成的导入，不覆盖已有变化。
- `scripts/backup_mongodb.py`：导出五类元数据为兼容原结构的 JSON，生成哈希清单；目标目录必须不存在。它不导出凭证、不复制媒体，也不是整台 MongoDB 的物理备份。

新环境先停旧后端写入，再运行以下命令，验证后开启 MongoDB 并启动一个 API worker。当前 231 已完成，无需重复导入。

```bash
# 231，工作目录 /data/aigc/lumenx
/home/zenking/miniconda3/envs/lumenx/bin/python scripts/migrate_json_to_mongodb.py
/home/zenking/miniconda3/envs/lumenx/bin/python scripts/migrate_json_to_mongodb.py --apply
```

本次线上回滚点：

- 旧代码、`.env`、requirements：`/data/aigc/lumenx/output/backups/mongodb_cutover_20261016T021140_732672Z/`
- 导入前 JSON 与哈希清单：`/data/aigc/lumenx/output/backups/pre_mongodb_20261016T021141_616025Z/`
- 切换回执：第一处目录下 `receipt.json`。

后续备份先暂停全部业务写入，确保跨集合快照一致，然后导出到一个新的目录，例如：

```bash
/home/zenking/miniconda3/envs/lumenx/bin/python scripts/backup_mongodb.py \
  --destination /data/aigc/lumenx/output/backups/mongodb_export_YYYYMMDD_HHMMSS
```

随后恢复后端，并单独备份媒体目录。导出脚本不自行停止服务。已经通过 mock 数据库的“导出 → 原格式 JSON → 新库导入”恢复测试；未在生产库做破坏性恢复演练。

需要回退 JSON 时，先停后端，导出**当前 MongoDB**，验证导出完整，再将这五个文件恢复到 `output/`，设 `LUMENX_STORAGE_BACKEND=json` 后启动。不要直接切回本次留下的旧 JSON，否则切换后的新项目与修改会丢失。连接故障时先恢复 MongoDB 再导出；不能把旧快照当最新数据。
