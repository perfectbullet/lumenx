# 多模态大模型的工业级AIGC漫剧智能生成系统

### 项目背景：

齐鲁工业大学\(山东省科学院\)

多模态大模型的工业级AIGC漫剧智能生成系统

简介：多模态大模型的工业级AIGC漫剧智能生成系统的研发及安装部署。培训及质保期内的技术支持与运维质保

**一、剧本解析与资产管理**

1、剧本多模态语义结构化解析：基于LLM对漫剧剧本做命名实体与情感抽取\(场景、角色道具、情感基调\)；长文本剧本向标准化分镜脚本智能切分，并自动生成支持跨模态调用的正负向提示词库。

2、智能资产库与角色管理：建立统一角色视觉特征档案，实现跨分镜角色快速索引；按题材对美术风格、环境光影向量化打标，实现美术资产多维层级化管理。

**二、漫剧智能生成与对齐**

1、跨模态视觉一致性评估与生成：基于扩散模型深度微调及LoRA混合注入，攻克多角度。多动作下角色面部及服饰跨帧一致性，建立动态防漂移校准机制；运用规则引擎和ControlNet等模型对画面做一致性校验和瑕疵识别。

2、情感化语音合成与智能时序对齐：基于零样本学习的情感语音合成算法，按剧本情感波动自动调节语调、语速及拟真语气；开发自动计算音视频时序长度的动态规划算法，实现画面、对白、BGM及字幕的自动化多轨对齐。

**三、剪辑、渲染与质量监控**

1、自动化剪辑与流水线合成：按分镜情感和节奏自动匹配推拉摇移等运镜效果及转场；算法驱动支持画中画、多机位视角切换等复杂合成逻辑，实现无人工干预下粗剪与精剪一键合成。

2、渲染队列与并发调度：开发支持多任务队列并发、分布式GPU节点渲染的后台调度系统，平衡各节点算力负载；记录每张图、每段音轨的生成参数、耗时及种子值，实现全链路日志留痕与异常追溯。

**四、支撑与运营管理**

1、模型工厂与参数配置：灵活定义并热插拔不同的基础大模型与LoRA微调包，设置权重比例、采样步数等关键参数。

2、权限与安全管理：按岗位分配不同的模型调用、数据查看和操作权限；记录所有用户关键操作与模型参数改动，满足数据安全和合规要求。

3、报表与吞吐量数据分析:自动生成日常业务报表\(每日渲染时长、生成帧数、模型调用频率等\);通过可视化图表动态展示系统并发规模、算法漂移率、合成效率等核心指标。

### 一、LumenX Studio 增强融合方案

**核心定位**：以 LumenX Studio 为产品化前端载体，通过插件化适配层注入 ManjuForge 分镜能力、多模型生成矩阵、分布式调度能力及现有基础设施，实现「开箱即用体验 \+ 工业级技术能力」的双重最优解

原因，是当前工业级漫剧教学场景投产比最高的技术路线—— 采用「LumenX 做上层业务交互与编排入口 \+ 双引擎能力做底层技术增强」的融合架构，落地速度接近纯 LumenX，能力完备性甚至超过纯双引擎组合方案，实现「1\+1\>2」的效果。

核心逻辑是，LumenX 强项在产品化的前端业务层（开箱即用、交互完善、全链路可视化），短板在底层生成、调度、工业级运维；双引擎组合强项在底层技术矩阵（多模型、分布式调度、专业运维），短板在上层业务交互与编排的产品化程度。两者恰好形成能力互补，无重叠冗余。

**1\.功能目标**：覆盖剧本解析、分镜生成、角色资产管理、多模型视频生成、音画对齐、自动剪辑、分布式渲染、运营监控全链路；

### 3\.2 ManjuForge 分镜引擎适配模块

模块编码：adapter\-manjuforge 核心作用：替换 LumenX 原生通用 LLM 分镜，注入工业级漫剧分镜能力

#### 3\.2\.1 技术实现

基于 FastAPI 开发独立适配服务，通过拦截 LumenX 的`/api/script/parse`接口请求，转发至 ManjuForge 引擎，将输出的八大标准化分镜字段映射转换为 LumenX 原生数据结构，前端无感知。

#### 3\.2\.2 核心处理流程

```Plain Text
1. 剧本预处理：清洗文本格式、识别章节标记、拆分长文本
2. 调用ManjuForge解析接口：传入剧本文本、分镜粒度、题材标签
3. 结构化解析输出：提取人设、场景、分镜、景别、运镜、情绪、提示词、时长八大字段
4. 格式映射转换：
   - ManjuForge分镜对象 → LumenX shot对象
   - 正负向提示词 → LumenX prompt字段
   - 情绪标签 → LumenX emotion扩展字段
5. 结果返回：按LumenX原生响应格式返回，前端直接渲染
```

### 3\.3 多模型生成矩阵适配层

**模块编码**：adapter\-model\-matrix **核心作用**：构建本地多模型混合引擎，替代原生云端模型调用，实现双精度、双档位的生成本地化

#### 3\.3\.1 模型矩阵配置

#### 3\.3\.2 模型适配器实现

基于 ComfyUI 核心封装标准模型推理服务，对外提供统一的 REST 接口；

内置模型加载、显存池化、批量推理、资源释放逻辑；

支持模型热切换，任务级自动匹配对应模型，无需重启服务。

#### 3\.3\.3 一致性校验流水线

嵌入生成流程后置环节，实现三级校验，不合格自动重抽：

**1\.结构校验**：ControlNet OpenPose/Depth 校验人物动作与场景结构匹配度；

**2\.身份校验**：Stand\-In 插件比对角色参考图特征相似度，低于阈值自动重生成；

**3\.瑕疵校验**：规则引擎检测人脸崩坏、穿模、色彩漂移，支持 3 次自动重抽，超过标记失败。

### 3\.4 OpenCue 分布式调度适配模块

模块编码：adapter\-opencue 核心作用：将LumenX 单节点任务队列升级为工业级分布式调度，支撑 30 路并发

#### 3\.4\.1 调度对接逻辑

1\.任务拦截：拦截 LumenX 原生生成任务，封装为 OpenCue 标准 Job 结构体；

2\.任务提交：通过 OpenCue Cuebot API 提交至调度集群，携带优先级、模型标签、资源需求；

3\.状态回调：订阅 OpenCue 任务状态事件，实时同步回 LumenX 业务层，映射为原生任务状态；

4\.结果回传：渲染完成后自动拉取成片文件，存入 LumenX 项目目录并同步至 NVR 存储。

#### 3\.4\.2 调度策略配置

#### 3\.4\.3 负载均衡算法

采用加权最小连接数 \+ 显存感知调度策略：

1\.实时采集各 GPU 节点显存占用、算力负载、任务队列长度；

2\.新任务优先分配至显存剩余充足、负载最低的节点；

3\.同型号 GPU 节点负载均衡偏差≤5%。

### 3\.5 基础设施对接适配层

#### 3\.5\.1 gRPC 通信引擎对接

1\.新增协议转换网关，将 LumenX 原生 REST 接口转换为标准 gRPC 接口，接入现有 gRPC 核心通信服务引擎；

2\.支持 Protobuf v3 序列化，复用现有服务发现、流量控制、安全鉴权能力。

#### 3\.5\.2 全域运维监控对接

1\.适配层内置 Prometheus 指标埋点，暴露任务数、成功率、耗时、模型调用频率等业务指标；

2\.GPU 节点、调度节点硬件指标复用现有采集链路，统一接入 Grafana 看板；

3\.日志统一输出至 Loki，支持全链路追踪与故障检索。

#### 3\.5\.3 NVR 存储对接

1\.新增存储回调钩子，成片生成后自动同步至现有 NVR 视频存储服务器；

2\.支持按班级、项目、日期分类存储，复用现有回放、点播能力。

## 四、接口与数据格式规范

### 4\.1 内部接口规范

#### 4\.1\.1 分镜解析接口

**1\.接口地址**：`/adapter/manjuforge/parse`

**2\.请求方式**：POST

**3\.请求参数**：

```Plain Text
{
  "script_text": "string // 剧本文本",
  "shot_duration": 5, // 单镜时长，秒
  "genre": "guofeng", // 题材标签
  "prompt_level": "standard" // 提示词精度
}
```

**响应参数**：LumenX 原生分镜结构，包含 shots 数组、characters 数组、scenes 数组

**错误码**： 

200：成功

400：参数错误

5001：ManjuForge 解析失败

5002：格式转换失败

#### 4\.1\.2 生成任务提交接口

**1\.接口地址**：`/adapter/model/generate`

**2\.请求方式**：POST

**3\.请求参数**：

```Plain Text
{
  "project_id": "string",
  "shot_id": "string",
  "prompt": "string",
  "negative_prompt": "string",
  "model_level": "train", // train/exam/quality
  "width": 768,
  "height": 1344,
  "frames": 125,
  "ref_image": "string // 参考图路径"
}
```

### 6\.2 性能压测方案

**1\.并发梯度压测**：分别以 10/20/30路并发提交生成任务，记录： 

平均生成耗时、P95 生成耗时；

各 GPU 节点显存、算力利用率；

任务成功率、失败率；

**2\.峰值压力测试**：30 路并发持续 10 分钟，验证系统稳定性与降级策略；

**3\.长稳测试**：24 小时连续运行，每小时提交 20 路任务，验证内存泄漏、显存泄漏。

### 6\.3 验收标准

1\.功能测试用例通过率 100%；

2\.60 路并发下，int4 模式平均生成耗时≤85 秒，P95 耗时≤95 秒；

3\.任务成功率≥98%；

4\.故障自动恢复成功率≥95%；

5\.全链路日志可追溯，监控指标完整展示。

### 6\.4 日常运维体系

**1\.监控告警**： Grafana 看板，配置 GPU 利用率、任务失败率、队列长度阈值告警；

**2\.巡检机制**：每日自动全链路健康巡检，生成巡检报告；

**3\.版本管理**：适配层模块独立版本号，支持灰度发布与回滚；

**4\.日志管理**：全链路日志留存 90 天，支持按任务 ID、用户、时间检索。

### 7\.4 故障处理流程

**1\.任务级故障**：自动重试 3 次，失败标记异常，告警通知管理员；

**2\.节点级故障**：OpenCue 自动标记节点下线，任务迁移至健康节点；

**3\.系统级故障**：保留 LumenX 原生单节点模式作为降级方案，调度集群故障时自动切回本地生成。
